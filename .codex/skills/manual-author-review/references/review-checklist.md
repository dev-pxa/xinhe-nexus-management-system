# 操作手册审查清单

审查 Agent 应逐项核对并记录证据；不适用的项目要说明原因。

## 事实一致性

- [ ] 文档中的菜单名称与路由配置一致。
- [ ] 文档中的页面标题与页面实际标题一致。
- [ ] 操作按钮、字段、弹窗标题和成功提示与页面代码一致。
- [ ] 角色名称、访问条件、数据范围和审批关系没有混用。
- [ ] 状态名称使用用户可理解的业务描述，不直接暴露内部枚举值。
- [ ] “已提交”“已锁定”“已开通”“已撤销”等结果与真实状态流转一致。

## 可操作性

- [ ] 新手可以从登录开始走完完整流程。
- [ ] 每个功能都有明确的进入路径。
- [ ] 每一步都能在页面上找到对应文字或控件。
- [ ] 步骤顺序符合实际页面交互，不遗漏必填项、确认按钮或返回动作。
- [ ] 写明成功后的可观察结果。
- [ ] 写明常见权限不足、数据为空、校验失败和链接失效的处理方式。

## 截图质量

- [ ] 关键步骤有真实截图，而不是占位图或纯文字描述。
- [ ] 截图来自当前代码版本和当前可运行页面。
- [ ] 图片路径正确，Markdown 中能够引用。
- [ ] 截图中的按钮、字段和菜单与文字说明一致。
- [ ] 截图配有图注，指出用户需要点击或观察的位置。
- [ ] 没有把临时截图、失败截图或敏感账号信息作为最终示例交付。

## 文档质量

- [ ] 一级标题和独立文件规则符合项目大纲。
- [ ] 标题层级连续，步骤编号连续，列表和表格可读。
- [ ] 没有 TODO、模板占位文字、错误链接或无证据的功能承诺。
- [ ] 没有把待开发模块写成当前可用功能。
- [ ] 没有修改与手册无关的业务代码。
